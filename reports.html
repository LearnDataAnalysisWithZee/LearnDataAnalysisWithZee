Researching Reports For Training Agents

Drill-down analytics or deeper analysis is in process, on-going research of reports that provides insights to train agents.

Operational Training

  • quotes today
    • query: product/product type
    • result: conversation scripts for each product/product type to be stored inside the agent toolbox (check data analysis ladder for more information on the recommended structure of a conversation script)
  • client query
    • query: client query against resolution
    • result:
      1. extract client query
      2. map one or more resolutions (can vary)
      3. search for keywords and enhance each conversation script
  • company query
    • query: company query against resolution
    • result:
      1. extract company query
      2. map one or more resolutions (can vary)
      3. search for keywords and enhance each conversation script
  • anomaly detected
    • query: anomaly detected against resolution
    • result:
      1. extract anomaly detected
      2. map one or more resolutions (can vary)
      3. search for keywords and enhance each conversation script
      4. create/update companywide rules and set/audit agent objectives
  • report reminder
    • query: contact details against date entry recorded
    • result:
      1. if there is an client or company query or anomaly detected that is unresolved then escalate to report reminder
      2. anomalies escalated to report reminder can be such as missing details of customer or customer requirement or missed calls/meetings after having been scheduled
      3. record contact details of company agent or customer, the date entry recorded and create a link to the report that contains the context or why the escalation such as snapshot of interaction from artefacts library
      4. keep track of pending escalations in the meanwhile trying to resolve/investigate them as soon as possible
      5. once the escalated matter has become resolved then do not immediately delete that until reporting back to update the report originally linked to so that can compute escalations later
    • point of sale guidance
  • query: customer details against customer documentation received, contract accepted
  • result:
    1. if customer has not objected to terms of contract and sent the required documentation then submit entry into this respective report stating so
    2. anomalies detected and escalated to report reminder if unresolved for longer than expected can be if customer documentation is still required or they have an objection against any terms that they would like to be re-considered that are negotiable
    3. record contact details of customer, and wether or not customer documentation has been recieved for each customer while the rest of this report being completed depends the commercial points of order this report covers
    4. if an anomaly is detected and recorded at during any time snapshot of interaction between customer-agent can be searched for customer profiling as can possibly be later determined as a fraudulent customer

Commercial Training

  • advertisement channels
    • query: product/product type against advertisment channel and conversion status
    • result:
      1. extract product/product type
      2. map one or more advertisement channels (can vary)
      3. create basic stats-keeping list consisting of advertisement channel, product/product type, count of advertisement channel leads & conversion status, segments
      4. across the timeline combine the daily findings from stats-keeping lists into an wider stats-keeping corpus
  • quotes today
    • query: agents note against product/product & pricing event (net)
    • result:
      1. extract from agents note strictly KPIs that are related to the transfer of the product from a business to the customer e.g. quoted, membership renewed, membership renewal request or purchased
      2. create KPI lists for each KPI extracted from agents note segment inside the quotes today report
      3. each list contains three segments, agents note (KPI), product/product type & pricing event (net)
      4. across the timeline combine the daily findings from KPI lists into an grander KPI corpus
  • quotes today for outliers flagged list{s}
    • query: agents note (KPI) against product/product type & pricing event (net)
    • result:
      1. extract from the KPI list, a KPI and an product/product type, and create a new outlier flagged list
      2. search the KPI list for pricing events that have a long range distance between them, where the KPI and product/product type match
      3. extend the outlier detected list to add, the extracted net pricing events that are either significantly low or high, also add the stakeholder involved if any at all between the customer and business such as an vendor and an investigation (why) segment
      4. the stakeholder information can be derived from the initial quotes today report
      5. various related data sources or past interactions can be used to conduct an investigation into possible reasons for these outliers
  • quotes today for outliers detected list{s}
    • query: agents note against product/product type
    • result:
      1. create a new outlier detected list consisting of the same segments the outliers flagged list did, agents note (outlier detected), policy type, stakeholder (vendor/mediator) & investigation (why)
      2. search the quotes today report inside the agents note segment for return/declined/cancellation or exchange/adjustment
      3. for each of the aformenetioned outliers extracted, get the policy type and stakeholder (vendor/company) too
      4. as is with the outlier flagged list, here too, various related data sources or past interactions can be used to conduct an investigation into possible reasons for these outliers
  • report reminder
    • query: contact details against date entry recorded
      • result:
      1. if there is an outlier detected that is unresolved then escalate to report reminder
      2. outliers detected of relevance to be entered as an reminder here if required can be to do with point of sale steps such as an existing customer not having adhered to their payment plan by missing payments or having provided mis-information about an unfortunate incident that ought to have informed about
      3. record contact details of company agent or customer, the date entry recorded and create a link to the report that contains the context or why the escalation such as snapshot of interaction from artefacts library
      4. keep track of pending escalations in the meanwhile trying to resolve/investigate them as soon as possible
      5. once the escalated matter has become resolved then do not immediately delete that until reporting back to update the report originally linked to so that can compute escalations later
    • point of sale guidance
  • query: customer details against payment method, payment{s} made and customer documentation dispatched
  • result:
    1. if a customer makes their due payment for the purchase of an product then submit entry into this respective report stating so
    2. anomalies detected and escalated to report reminder if unresolved for longer than expected can be if they have not made a payment as per payment plan they had promised to pay according to, to the extent that they would like the payments amount be re-considered, and this is non-negotiable therefore for in order to be able to forward for the next action to be taken in that respect
    3. record contact details of customer, the method of payment and wether or not each payment as per payment plan (if customer has set payment plan in motion) and most importantly an confirmation they have received the documentation that is their due right to possess
    4. if customer has lost their documentation and would like a confirmation of previous purchase or for documentation to be re-sent then this record would serve as sufficient for such a task also
    5. if an anomaly is detected and recorded at during any time snapshot of interaction between customer-agent can be searched for customer profiling as can possibly be later determined as a fraudulent customer
